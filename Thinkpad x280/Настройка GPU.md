Для Intel UHD (особенно 6-го поколения и новее) рекомендуется установить "несвободную" версию, которая включает все функции аппаратного ускорения в таких приложениях, как MPV, VLC, Firefox и Chromium.

## Установка драйверов для аппаратного ускорения видео (VA-API)

1. Установка драйверов:
```bash
sudo apt install intel-media-va-driver-non-free
```

2. Установка утилиты `vainfo`
```bash
sudo apt install vainfo
```

Это утилита командной строки для проверки поддержки аппаратного ускорения видео (VA-API) в Linux, включая Lubuntu. После установки необходимо перезагрузить компьютер и выполнить команду:
```bash
vainfo
```
- Выведется список поддерживаемых профилей (VAProfile...). 
- Строка с версией драйвера должна содержать `iHD` (Intel High Definition), что подтверждает использование нужного драйвера.

## Конфликт драйвера `intel` на Intel UHD 620: суть проблемы
### Что происходит на старом драйвере `intel`

Драйвер `xserver-xorg-video-intel` — это legacy-драйвер, который когда-то был основным для графики Intel. На современных системах (особенно с ядрами 5.x+) он конфликтует с инфраструктурой аппаратного ускорения видео.

**Корень конфликта:**

| Компонент                    | Что требует                                                 | Результат                                                                  |
| :--------------------------- | :---------------------------------------------------------- | :------------------------------------------------------------------------- |
| **Celluloid / MPV (VA-API)** | Требует `DRI3` для доступа к аппаратному декодированию      | При включении `Option "DRI" "3"` — ускорение работает                      |
| **Браузер / Камера (X11)**   | Требуют корректной работы `TearFree`                        | При включении `Option "DRI" "3"` — `TearFree` ломается, появляются разрывы |
| **Сам драйвер `intel`**      | Не умеет одновременно держать `DRI3` и `TearFree` стабильно | Вы вынуждены выбирать: либо ускорение в плеере, либо плавность в браузере  |

**Почему так происходит:**
Драйвер `intel` использует собственный метод управления буферами кадров (SNA/UXA), который при активном DRI3 перестаёт корректно синхронизировать вывод с частотой обновления монитора. Это известный баг, который разработчики не стали исправлять, поскольку сам драйвер признан устаревшим и заменён на встроенный в ядро `modesetting`.

### Почему `modesetting` решает проблему

Драйвер `modesetting`:
- Встроен в Xorg и ядро Linux, не требует установки отдельных пакетов.
- Использует современный метод ускорения **glamor** (2D через OpenGL).
- Имеет нативную и стабильную поддержку **DRI3**, что даёт аппаратное ускорение в Celluloid.
- **Не имеет встроенного механизма TearFree**, поэтому сам по себе не борется с разрывами.

**Решение:** Мы убираем конфликтный драйвер `intel` (опционально) и передаём задачу устранения разрывов внешнему композитору **Picom**.

## Краткий гайд: настройка `modesetting` + Picom
### ⚠️ Важное предварительное условие: сессия X11, а не Wayland

Данный гайд предназначен **только для X11**. Picom — это композитор для X-сервера, и он **не будет работать в сессии Wayland**.

**Как проверить, в какой сессии вы находитесь:**
```bash
echo $XDG_SESSION_TYPE
```
- Если вывод `x11` — всё правильно, продолжайте.
- Если вывод `wayland` — вам нужно выйти из системы и на экране входа выбрать сессию **без** пометки "Wayland" (обычно через значок шестерёнки или меню выбора сессии).

> **Примечание:** В Wayland разрывы кадров устраняются встроенным композитором, и проблема конфликта `DRI3`/`TearFree` там отсутствует по определению. Если вы используете Wayland, этот гайд вам не нужен.

---

### Шаг 1: Убедиться, что используется `modesetting`

**Вариант А: Удалить старый драйвер (рекомендуется)**
```bash
sudo apt purge xserver-xorg-video-intel
sudo rm -f /etc/X11/xorg.conf.d/20-intel.conf
```

**Вариант Б: Оставить драйвер, но принудительно переключиться на `modesetting`**

Создайте файл `/etc/X11/xorg.conf.d/10-modesetting.conf`:
```ini
Section "OutputClass"
    Identifier  "Intel Graphics"
    MatchDriver "modesetting"
    Driver      "modesetting"
    Option      "AccelMethod"    "glamor"
EndSection
```

Даже если `xserver-xorg-video-intel` установлен, наличие этого файла и отсутствие конфликтующего `20-intel.conf` с `Driver "intel"` заставит систему использовать `modesetting`.

### Шаг 2: Проверить, какой драйвер активен

После перезагрузки выполните:
```bash
cat /var/log/Xorg.0.log | grep -i "modesetting\|intel"
```

**Ожидаемый результат (modesetting активен):**
```
[    12.345] (II) modeset(0): Driver loaded and initialized
[    12.345] (==) modeset(0): Depth 24, (==) framebuffer bpp 32
[    12.345] (II) modeset(0): glamor X acceleration enabled
```

Если вы видите `intel(0): Driver loaded`, значит старый драйвер всё ещё активен — удалите его или проверьте, не осталось ли файлов `20-intel.conf`.

### Шаг 3: Установка и настройка Picom

**Установка:**
```bash
sudo apt install picom
```

**Создание конфига** `~/.config/picom/picom.conf`:

```ini
# ~/.config/picom/picom.conf

# Бэкенд XRender — наиболее стабилен для Intel UHD 620
backend = "xrender";

# Ключевая опция: устраняет разрывы (tearing)
vsync = true;

# Отключаем прозрачность — делаем всё как было до picom
active-opacity = 1.0;
inactive-opacity = 1.0;
frame-opacity = 1.0;
opacity-rule = [];

# Отключаем тени и эффекты затухания (для производительности)
shadow = false;
fading = false;

# Запрещаем picom "отпускать" окна, которые якобы не имеют разрывов
unredir-if-possible = false;

# Убираем задержки и артефакты
detect-transient = true;
detect-client-leader = true;
```

**Запуск Picom:**
```bash
# Убить старый процесс (если есть)
pkill picom

# Запустить с новым конфигом
picom --config ~/.config/picom/picom.conf &
```

### Шаг 4: Добавление Picom в автозагрузку

Добавьте команду `picom --config ~/.config/picom/picom.conf &` в настройки автозапуска вашего окружения рабочего стола (например, через `gnome-session-properties` или соответствующий пункт в настройках XFCE/Cinnamon).

1. **Создайте папку для автозагрузки**, если её еще нет:
```
mkdir -p ~/.config/autostart
```

2. **Создайте файл** `picom.desktop`:
```bash
nano ~/.config/autostart/picom.desktop
```

3. **Скопируйте и вставьте** в этот файл следующее содержимое:
```ini
[Desktop Entry]
Type=Application
Name=Picom Compositor
Comment=A lightweight X11 compositor for tear-free experience
Exec=picom --config ~/.config/picom/picom.conf
StartupNotify=false
Terminal=false
Hidden=false
```
- **`Exec=picom --config ~/.config/picom/picom.conf`** — это и есть ключевая строка. Она явно указывает системе запустить `picom` с вашим конфигурационным файлом.
- **`Hidden=false`** — гарантирует, что запись активна и будет выполнена.

4. Сохраните файл и закройте редактор

Теперь после перезагрузки или повторного входа в систему Picom будет запускаться автоматически с нужными вам настройками.
### Шаг 5: Альтернативный бэкенд (если XRender не подошёл)

Если разрывы сохранились, замените в конфиге `backend = "xrender";` на:
```ini
backend = "glx";
glx-no-stencil = true;
```

## Итог: что вы получаете

| Компонент | Результат |
| :--- | :--- |
| **Celluloid / MPV** | Аппаратное ускорение VA-API работает через DRI3 без ошибок |
| **Браузер (YouTube)** | Нет разрывов кадров благодаря `vsync = true` в Picom |
| **Запись с камеры** | Плавное отображение без tearing |
| **Окна** | Полностью непрозрачные, как до установки Picom |

Эта конфигурация устраняет конфликт между DRI3 и TearFree в сессии X11, перекладывая задачу синхронизации на внешний композитор, который справляется с ней стабильно и без побочных эффектов.
