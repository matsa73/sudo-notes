На большинстве ноутбуков Lenovo X280 используется `Synaptics` (или иногда `Validity`/``Synaptics``), который часто требует дополнительной настройки в Linux.
### Шаг 1: через `fprintd`

Это стандартный стек для отпечатков в Linux (используется в `Gnome` / `KDE` / `Ubuntu`). В `Lubuntu` он тоже должен работать.

1.  Открыть терминал (`Ctrl+Alt+T`).
2.  Установить необходимые пакеты:
```bash
sudo apt update
sudo apt install fprintd libpam-fprintd
```
*   `fprintd` — это демон (служба) для работы с отпечатками.
*   `libpam-fprintd` — модуль, который позволяет использовать отпечаток для входа в систему (PAM — это механизм аутентификации).

3.  Проверить, видит ли система сканер:
```bash
fprintd-list
```
Если система выведет что-то вроде `Found a device`, значит, повезло — драйвер подошел.

4.  Записать отпечаток пальца:
```bash
fprintd-enroll
```
*   Система попросит приложить палец несколько раз. По умолчанию записывается палец, который использовался первым (обычно правый указательный).
*   Если несколько пользователей, или есть необходимость записать палец для конкретного пользователя:
```bash
fprintd-enroll -f "ЛЕВЫЙ_УКАЗАТЕЛЬНЫЙ" имя_пользователя
```

5.  Настройка входа в систему:
*   После установки `libpam-fprintd`, система должна автоматически добавить отпечаток как опцию входа.
*   Теперь при попытке войти в систему, запуске команд через `sudo` или разблокировке экрана, система попросит либо пароль, либо прикосновение пальца.

6.  Проверка и управление:
*   Посмотреть сохраненные отпечатки: `fprintd-list имя_пользователя`
*   Удалить все отпечатки: `fprintd-delete имя_пользователя`
### Шаг 2: Проверка совместимости и диагностика

1. Узнать точную модель сканера:
```bash
lsusb
```
Найти строку, содержащую слова `Fingerprint`, `Synaptics`, `Validity` или `06cb` (часто это код `Synaptics`). Пример вывода: `06cb:009a Synaptics, Inc.`

2. Свериться с базой совместимости `libfprint`:
Перейти на официальную страницу поддерживаемых устройств проекта [libfprint](https://fprint.freedesktop.org/supported-devices.html) или просто вбить в Google код  устройства (например, `06cb:009a`).
*   Если устройство там есть — нужно разбираться, почему не подхватилось (возможно, старая ОС).
*   Если устройства нет — скорее всего, на `Lubuntu` оно работать не будет.
### Шаг 3: настройка `python-validity`

Если стандартный `fprintd` не видит сканер, возможно, эта модель, которая требует проприетарного драйвера или работает через `libfprint` из нового репозитория.

Можно попробовать установить более свежую версию `libfprint` из проекта FPC (часто используется в новых Lenovo).

Процесс состоит из нескольких этапов: удаление стандартного пакета, подключение специального репозитория, установка драйвера и, возможно, сброс настроек чипа.

1. Удалить стандартный пакет `fprintd`, если он был установлен ранее. Это нужно для избежания конфликтов.
```bash
sudo apt remove fprintd
```

2. Добавить PPA (Personal Package Archive) `uunicorn/open-fprintd`. Именно здесь находятся собранные пакеты `python-validity` и `open-fprintd`.
```bash
sudo add-apt-repository ppa:uunicorn/open-fprintd
```

3. Обновить список пакетов и установить необходимые компоненты:
```bash
sudo apt update
sudo apt install open-fprintd fprintd-clients python3-validity
```
* `open-fprintd` — это форк `fprintd`, работающий в связке с `python-validity`.
* `fprintd-clients` — утилиты для управления (например, `fprintd-enroll`).
* `python3-validity` — сам драйвер.

4.  Попробовать записать отпечаток стандартной командой:
```bash
fprintd-enroll
```
Если команда выполнится успешно и попросит приложить палец — всё работает! Переход к шагу 6.

5. Если возникла ошибка (например, `list_devices failed:`) — это нормально для первого запуска. Часто требуется выполнить сброс (factory reset) чипа, как описано в разделе "Error situations" репозитория. Необходимо выполнить следующие команды по порядку:
```bash
# Останавливаем сервис, если он запущен
sudo systemctl stop python3-validity

# Сбрасываем прошивку сенсора (важно!)
sudo validity-sensors-firmware

# Выполняем полный сброс настроек чипа до заводских
sudo python3 /usr/share/python-validity/playground/factory-reset.py

# Запускаем сервис заново
sudo systemctl start python3-validity

# Снова пробуем записать отпечаток
fprintd-enroll
```
Если какая-то из команд пожалуется на "device busy", значит, сервис `python3-validity` не до конца остановился. Необходимо повторить `sudo systemctl stop python3-validity` и попробовать снова.

6. Чтобы включить аутентификацию по отпечатку для входа в систему после успешной записи отпечатка, нужно разрешить системе использовать его. В `Lubuntu` это делается через `pam-auth-update`:
```bash
sudo pam-auth-update
```
В открывшемся псевдографическом меню с помощью пробела необходимо отметить галочкой пункт `Fingerprint authentication` (или похожий). С помощью Tab перейти на `Ok` и нажать `Enter`.

7. Перезагрузить систему, чтобы изменения гарантированно вступили в силу.
```bash
sudo reboot
```
## Возможные проблемы и их решение

### 1. Не работает после сна/гибернации: 

Как указано в инструкции, нужно включить специальные сервисы:
```bash
sudo systemctl enable open-fprintd-resume open-fprintd-suspend
```

Но даже с включенными сервисами `open-fprintd-resume` и `open-fprintd-suspend`, датчик отпечатков пальцев (особенно на ноутбуках с сенсорами `Synaptics`, которые использует `python3-validity`) часто "засыпает" слишком глубоко и корректно не просыпается.
#### Вариант 1. Создание собственного правила пробуждения

Сервисы `open-fprintd-resume` часто срабатывают слишком рано, когда устройство еще не готово. Лучше создать правило `udev`, которое будет перезапускать сервис при пробуждении системы.
1. Файл с правилами:
```bash
sudo nano /etc/udev/rules.d/99-fingerprint-resume.rules
```

2. Правила:
```bash
ACTION=="add", SUBSYSTEM=="usb", DRIVERS=="usb", ATTRS{idVendor}=="06cb", ATTRS{idProduct}=="009a", RUN+="/bin/systemctl restart python3-validity"
```
**Важно:** узнать `idVendor` и `idProduct` можно с помощью команды `lsusb`
**Вывод команды**: `Bus 001 Device 008: ID 06cb:009a Synaptics, Inc.`
Вот эти значения `06cb:009a` и нужно подставить в правило выше (после `idVendor` и `idProduct`).

3. Перезагрузка и применение правил `udev`
```bash
sudo udevadm control --reload-rules
sudo udevadm trigger
```

При использовании этого варианта возникает ==проблема== долгой загрузки системы ~2 мин. Почему так происходит: `systemd-udev-settle.service` имеет встроенный таймаут 120 секунд (2 минуты). Если какое-то `udev` правило зависает или долго выполняется, система ждёт именно столько.
#### Вариант 2. Использовать системные хуки сна/пробуждения 

Логика исправления сканера выносится в **системный сервис (systemd unit)**, который запускается после выхода из сна.

```bash
sudo nano /usr/lib/systemd/system-sleep/fingerprint-resume.sh
```

Содержимое скрипта:
```bash
#!/bin/bash
case $1 in
    post)
        sleep 3
        systemctl restart python3-validity
        echo "fingerprint: fixed after $2" | logger
        ;;
esac
```

Сделать скрипт исполняемым:
```bash
sudo chmod +x /usr/lib/systemd/system-sleep/fingerprint-resume.sh
```

Чтобы убедиться, что скрипт отработал можно посмотреть лог с помощью следующей команды:
```bash
journalctl | grep "fingerprint: fixed after"
```
