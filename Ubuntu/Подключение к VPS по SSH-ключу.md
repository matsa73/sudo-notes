# Подключение к VPS по SSH-ключу

## Настройка SSH-ключей

1. Генерация ключа (на компьютере, с которого идёт подключение к VPS):

    ```bash
    # -t ed25519 - указывает тип ключа (Ed25519, более безопасный и быстрый, чем RSA)
    # -C "vps-ключ" — комментарий к ключу (обычно используется для идентификации ключа)
    ssh-keygen -t ed25519 -C "vps-key"
    ```

2. Система задаст несколько вопросов:

    ```text
    Generating public/private ed25519 key pair.
    Enter file in which to save the key (/home/user/.ssh/id_ed25519):
    ```

3. Нажать `Enter`, чтобы сохранить в предложенную папку, или указать свой путь

    ```text
    Enter passphrase (empty for no passphrase):
    Enter same passphrase again:
    ```

4. Можно ввести пароль для дополнительной защиты приватного ключа или оставить пустым, нажав `Enter`. Пароль шифрует приватный ключ на диске. Если кто-то получит доступ к файлу приватному ключу, то без пароля он не сможет им воспользоваться.
5. После успешной генерации:

    ```text
    Your identification has been saved in ~/.ssh/id_ed25519
    Your public key has been saved in ~/.ssh/id_ed25519.pub
    The key fingerprint is:
    SHA256:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx vps-key
    ```

## Где находятся файлы ключей?

- **Приватный ключ:** `~/.ssh/id_ed25519` (никому не передавать!)
- **Публичный ключ:** `~/.ssh/id_ed25519.pub` (можно копировать на серверы)

## Как использовать?

- Просмотр публичного ключа

    ```bash
    cat ~/.ssh/id_ed25519.pub
    # ssh-ed25519 xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx vps-key
    ```

- Копирование на сервер и выставление прав на стороне сервера

    Правильные права на сервере обязательны: если они слишком открытые, SSH молча откажется использовать ключ, даже если всё скопировано верно.

    ```bash
    cat ~/.ssh/id_ed25519.pub | ssh root@server_ip "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
    ```

    Альтернатива — команда `ssh-copy-id`, которая делает то же самое и сама выставляет права:

    ```bash
    ssh-copy-id -i ~/.ssh/id_ed25519.pub root@server_ip
    ```

    При первом подключении SSH спросит про fingerprint сервера:

    ```text
    Are you sure you want to continue connecting (yes/no)?
    ```

    Это нормально — вводим `yes`, ключ сервера сохранится в `~/.ssh/known_hosts`.

## Настройка для удобства

1. Создать папку и выставить права:

    ```bash
    mkdir -p ~/.ssh
    chmod 700 ~/.ssh
    ```

2. Если ключ был сгенерирован не в стандартном месте (например, скачан или перенесён с другого устройства) — скопировать его в `~/.ssh`:

    ```bash
    cp /путь/к/ключу/id_ed25519 ~/.ssh/id_ed25519
    chmod 600 ~/.ssh/id_ed25519
    ```

    Если ключ уже создан по умолчанию в `~/.ssh/id_ed25519` (шаг 3 из первого раздела), этот пункт можно пропустить.

3. Создать файл `~/.ssh/config` в кодировке UTF-8 БЕЗ BOM на компьютере, с которого будет осуществляться подключение к VPS:

    ```bash
    nano ~/.ssh/config
    ```

    ```text
    Host myvps
        HostName server_ip
        User root
        Port 22
        IdentityFile ~/.ssh/id_ed25519
        IdentitiesOnly yes
    ```

    `IdentitiesOnly yes` заставляет SSH использовать именно указанный ключ, а не перебирать все ключи из `ssh-agent` — полезно, если ключей несколько, иначе можно словить ошибку `Too many authentication failures`.

4. Выставить права на конфиг:

    ```bash
    chmod 600 ~/.ssh/config
    ```

5. Проверить всё перед подключением:

    ```bash
    # Проверка структуры и прав
    ls -la ~/.ssh/
    ```

    ```text
    drwx------ 2 user user 4096 ... .ssh/
    -rw------- 1 user user  200 ... config
    -rw------- 1 user user  411 ... id_ed25519
    ```

6. Теперь подключаться можно так:

    ```bash
    ssh myvps
    ```

## Отключить вход по паролю

**Важно:** перед отключением пароля обязательно убедиться, что вход по ключу работает. Для этого:

1. Не закрывая текущую (парольную) сессию, открыть **новое окно терминала**.
2. Попробовать подключиться командой `ssh myvps`.
3. Убедиться, что вход прошёл без запроса пароля.

    Если новая сессия не открывается — не отключать пароль, пока проблема не будет найдена. Иначе при ошибке в ключах или конфиге доступ к серверу можно потерять полностью.

4. Открыть конфигурационный файл

    ```bash
    nano /etc/ssh/sshd_config
    ```

5. Изменить:

    ```text
    # Запретить вход по паролю
    PasswordAuthentication no

    # Запретить вход с пустым паролем
    PermitEmptyPasswords no

    # Разрешить вход только по ключам (рекомендуется)
    PubkeyAuthentication yes

    # Запретить вход по паролю для root, но оставить вход по ключу (рекомендуется для безопасности)
    PermitRootLogin prohibit-password
    ```

6. Перезапустить SSH:

    ```bash
    # На Ubuntu/Debian служба называется "ssh", а не "sshd"
    systemctl restart ssh
    ```

7. Проверить статус, чтобы убедиться, что служба запустилась без ошибок:

    ```bash
    systemctl status ssh
    ```

8. **Не закрывая текущую сессию**, открыть ещё одно новое окно терминала и снова проверить `ssh myvps` — только после успешной проверки закрывать старые сессии.
