# Подключение к VPS

## Linux/Windows

1. **Сгенерировать ключ** на компьютере, с которого осуществляется подключение. Можно использовать общий `id_ed25519` или отдельный под конкретный сервер;
2. **Скопировать публичный ключ на сервер** — `ssh-copy-id` или ручной способ (для Windows);
3. **Добавить алиас в `~/.ssh/config`** — дальше подключение просто `ssh my_server`;
4. **Проверить вход по ключу до отключения пароля**: не закрывая текущую (парольную) сессию, открыть новое окно терминала и подключиться `ssh my_server` — вход должен пройти без запроса пароля.

   ❗Если новая сессия не открывается — не отключать пароль, пока проблема не найдена. Иначе при ошибке в ключах или конфиге можно потерять доступ к серверу полностью.❗

5. **Отключить парольный вход** — на сервере, в `/etc/ssh/sshd_config`:

    ```text
    PasswordAuthentication no
    PermitEmptyPasswords no
    PubkeyAuthentication yes
    PermitRootLogin prohibit-password
    ```

6. **Перезапустить и проверить службу**:

    ```bash
    # На Ubuntu/Debian служба называется "ssh", а не "sshd"
    systemctl restart ssh
    systemctl status ssh
    ```

7. **Ещё раз проверить в новом окне терминала**, не закрывая старую сессию — и только после успешной проверки закрывать старые сессии.

## Android (`Termux`)

Общие принципы — генерация ключа, структура `~/.ssh`, `authorized_keys`, `ssh-agent` — на `Termux` работают так же. Отличия только в окружении: нет systemd, свой пакетный менеджер (`pkg`, поверх APT), и ключи хранятся в песочнице приложения, а не в обычном `$HOME` пользователя Linux.

1. Установка `Termux`
    Ставить **только из F-Droid или GitHub-релизов**, не из Google Play — версия в Play Store давно не обновляется и не совместима с актуальными пакетами.

    - F-Droid: <https://f-droid.org/packages/com.termux/>
    - GitHub: <https://github.com/termux/termux-app/releases>

2. Установка SSH-клиента

    ```bash
    pkg update && pkg upgrade
    pkg install openssh
    ```

    Пакет `openssh` в `Termux` включает и клиент, и `ssh-copy-id`, и `sshd` (последний не нужен, если телефон выступает только клиентом, а не сервером).

3. Ключ для телефона

    Рекомендуется отдельный ключ под телефон (а не копия основного с рабочей машины) — так его проще отозвать при потере телефона, не трогая доступ с других устройств.

    `$HOME` в `Termux` — это `/data/data/com.termux/files/home`, но обращаться к нему можно как обычно, через `~`.

4. Копирование публичного ключа на сервер

    Если `ssh-copy-id` не срабатывает (например, пароль ещё не подтверждён на сервере) — ручной способ тот же, что в разделе 2: вывести `cat ~/.ssh/id_ed25519.pub` и вставить строку в `~/.ssh/authorized_keys` на сервере.

5. Алиас в `~/.ssh/config`
6. Проверка подключения

    ```bash
    ssh -i ~/.ssh/id_ed25519 'user@server_ip'
    ```

    ```bash
    ssh my_server
    ```

    ❗Как и с десктопом — не отключать парольный вход на сервере, пока вход по ключу с телефона не подтверждён.❗

7. Специфика `Termux`

    - **Wake lock.** Android агрессивно замораживает фоновые процессы. Для длинных сессий (например, `screen`/`tmux` на сервере через SSH) стоит удерживать процессор:

        ```bash
        termux-wake-lock   # снять: termux-wake-unlock
        ```

    - **Extra keys row.** У Android-клавиатуры нет физических `Ctrl`, `Esc`, `Tab`, `|`, `/` — без них неудобно работать в терминале и `vim`/`nano` на сервере. Настраивается в `~/.termux/termux.properties`:

        ```text
        extra-keys = [['ESC','CTRL','ALT','TAB','|','/','-','HOME','END']]
        ```

    После правки — `termux-reload-settings`.

    - **Хранение ключа.** Приватный ключ должен оставаться в приватной песочнице `Termux` (`~/.ssh`), а не в общем хранилище (`~/storage/...` посл  `termux-setup-storage`) — общее хранилище доступно другим приложениям с разрешением на файлы.
    - **Бэкап ключа.** Не синхронизировать приватный ключ через облако или git (даже приватный репозиторий) в открытом виде. Если нужен бэкап — только зашифрованный (например, `age` или `gpg`), отдельно от остальных заметок.
    - **Блокировка телефона.** PIN/биометрия на телефоне — по сути первая линия защиты ключа: если экран не заблокирован, ключ доступен любому, у кого телефон в руках.
    - **Автозапуск `ssh-agent`.** Systemd-юнита, как на десктопе, нет — если используется парольная фраза на ключе, `ssh-agent` стартуют вручную или добавляют в `~/.bashrc`:

        ```bash
        eval "$(ssh-agent -s)" > /dev/null
        ssh-add -l >/dev/null 2>&1 || ssh-add ~/.ssh/id_ed25519
        ```

8. Диагностика

    ```bash
    ssh -v my_server # подробный вывод для отладки
    termux-info      # версия `Termux` и пакетов, полезно при багрепортах
    ```
