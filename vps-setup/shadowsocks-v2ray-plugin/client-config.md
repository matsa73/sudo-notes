# Настройка клиентской части shadowsocks + v2ray-plugin

Установка shadowsocks + v2ray-plugin полностью совпадает с конфигурацией сервера (см. п1-3)

## 1. Конфигурация

Имя файла конфигурации для клиентской части `local-config.json`, а не `config.json` — последнее имя занято дефолтным юнитом `shadowsocks-libev.service`, работающим в режиме **сервера**.

Пример конфигурационного файла: [local-config.json](local-config.json)

```bash
sudo nano /etc/shadowsocks-libev/local-config.json
```

| Параметр        | Значение                              | Описание                                                                    |
| --------------- | ------------------------------------- | --------------------------------------------------------------------------- |
| `server`        | `<SERVER_IP>`                         | IPv4 адрес сервера                                                          |
| `server_port`   | `443`                                 | Порт сервера                                                                |
| `local_address` | `127.0.0.1`                           | Адрес SOCKS5-прокси                                                         |
| `local_port`    | `1080`                                | Порт SOCKS5-прокси                                                          |
| `password`      | `<PASSWORD>`                          | Пароль для подключения                                                      |
| `timeout`       | `60`                                  | Таймаут неактивного соединения                                              |
| `method`        | `chacha20-ietf-poly1305`              | Метод шифрования                                                            |
| `mode`          | `tcp_only`                            | Режим работы прокси-сервера (только TCP, UDP не проксируется)               |
| `plugin`        | `v2ray-plugin`                        | Имя бинарника плагина (должен находиться в PATH, например `/usr/local/bin)` |
| `plugin_opts`   | `host=www.microsoft.com;path=/;mux=0` | Параметры плагина: подменяемый Host, путь, mux                              |

## 2. Включение клиента как systemd-сервис

1. Отключить ненужный серверный юнит:

    ```bash
    sudo systemctl disable --now shadowsocks-libev
    ```

2. Включить и запустить клиентский туннель:

    ```bash
    sudo systemctl enable --now shadowsocks-libev-local@local-config.service
    ```

    `enable` — автозапуск при загрузке ОС, `--now` — сразу же запустить, не дожидаясь перезагрузки. Теперь это обычный фоновый сервис — systemd сам поднимет его при старте ОС и перезапустит при падении.

3. Проверить статус и логи:

    ```bash
    sudo systemctl status shadowsocks-libev-local@local-config.service
    journalctl -u shadowsocks-libev-local@local-config.service -n 50
    ```

4. Проверить, что туннель реально работает:

    ```bash
    sudo ss -ltnp | grep 1080 # проверить, что ss-local действительно слушает порт
    curl -x socks5h://127.0.0.1:1080 https://ifconfig.me --max-time 10
    ```

    IP в ответе должен быть IP-адресом VPS, а не локальным.

## 3. Установка и настройка локального HTTP-proxy

Некоторые программы (например, VS Code) не умеют работать с SOCKS5 напрямую. Решение — `privoxy`. Это лёгкая утилита-конвертер, которая поднимает локальный HTTP-прокси и перенаправляет трафик в SOCKS5. Она не создаёт отдельное соединение, а просто «переводит» протокол; ресурсов почти не потребляет.

1. Установка:

    ```bash
    sudo apt install privoxy
    ```

2. Проверка адреса прослушивания

    ```bash
    grep -n "^listen-address" /etc/privoxy/config
    ```

    В выводе должна быть активная строка (без `#`) вида `listen-address 127.0.0.1:8118`. В Debian/Ubuntu она обычно есть из коробки, тогда ничего менять не нужно.

3. Добавить форвардинг в SOCKS5

    Сначала убедитесь, что своих forward-правил ещё нет:

    ```bash
    grep -n "^forward" /etc/privoxy/config
    ```

    Вывод должен быть пустым. Добавить строку в конец файла:

    ```bash
    sudo nano /etc/privoxy/config
    ```

    ```text
    forward-socks5 / 127.0.0.1:1080 .
    ```

    - `/` — правило действует для всех URL;
    - `127.0.0.1:1080` — адрес вашего `ss-local` (значение `local_port`);
    - `.` в конце обязательна: она означает «без вышестоящего HTTP-прокси».

4. Применение настроек:

    ```bash
    sudo systemctl restart privoxy
    sudo systemctl enable privoxy
    ```

5. Проверка:

    ```bash
    sudo ss -ltnp | grep 8118 # проверить, что privoxy слушает порт
    curl -x http://127.0.0.1:8118 https://ifconfig.me --max-time 10
    ```

    IP должен совпасть с тем, что показывал `curl` через SOCKS5 (раздел 2, п. 4) — значит вся цепочка работает:

    ```text
    Приложение (HTTP-запрос)
        → Privoxy — конвертирует HTTP в SOCKS5
        → SOCKS5-прокси (shadowsocks + v2ray-plugin клиент)
        → VPS-сервер (shadowsocks + v2ray-plugin сервер)
        → Интернет
    ```

6. Опционально — отключить фильтрацию

    По умолчанию Privoxy может фильтровать рекламу и подставлять собственные страницы вместо сайтов, а также показывать свою страницу ошибки, если туннель недоступен. Содержимое HTTPS-страниц Privoxy не изменяет, но запросы к некоторым доменам может блокировать.

    Чтобы отключить фильтрацию Privoxy, необходимо добавить в конец файла `/etc/privoxy/user.action` (файл читается последним и перекрывает остальные правила):

    ```bash
    sudo nano /etc/privoxy/user.action
    ```

    ```text
    { -block -filter }
    /
    ```

    - `{ -block -filter }` — отключить блокировку и фильтры;
    - `/` — применять ко всем адресам. Эта строка должна быть без отступа и на отдельной строке сразу под фигурными скобками.

    Это отключает блокировку и все фильтры для всех адресов, остальные файлы трогать не нужно.

    После применения изменений необходимо перезапустить privoxy, а затем повторить проверку соединения.
